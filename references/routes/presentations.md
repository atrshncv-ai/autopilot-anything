# Presentations route

Use when the primary deliverable is a slide deck. Inputs: audience, purpose, key message, length, language, visual constraints or template, source material, and available authoring/rendering tools.

1. Confirm the narrative and slide-level structure against the request; identify evidence and any claims needing verification. For factual claims, use current primary/authoritative sources where appropriate, with URLs and dates near the claim; distinguish evidence from hypothesis and inference.
2. Create an editable deck in a suitable format and preserve its source. Add a PDF or other export only when useful or requested. Keep charts, citations, and notes traceable to their underlying material.
3. Render the deck when available and inspect every slide for clipping, legibility, layout consistency, and content errors; check file structure/openability as the tools allow.

Quality means a coherent audience-fit story, supported claims, editable source, and a usable visual result. If authoring or rendering is unavailable, provide the editable source or a clearly labeled slide outline and state exactly which visual checks were not run; never claim an unseen render passed.
