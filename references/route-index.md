# Route index

Choose a route by the main deliverable. Load only the relevant route instructions, then use the shared workflow and safety rules. Use more than one profile only when the request has distinct deliverables that need different methods.

| Main deliverable | Route |
| --- | --- |
| Change or build software, investigate a codebase, or fix a technical issue | [Code](routes/code.md) |
| Scientific question, literature review, hypothesis, or research paper | [Scientific research](routes/scientific-research.md) |
| Current facts, comparison, market or policy research, or sourced briefing | [Information gathering](routes/information-gathering.md) |
| Explore, transform, interpret, or report structured data | [Data analysis](routes/data-analysis.md) |
| Create or revise a slide deck | [Presentations](routes/presentations.md) |
| Create or revise a document or another file artifact | [Documents and files](routes/documents-and-files.md) |
| Household, physical, administrative, service, or other work without a matching profile | [General work](routes/general.md) |

For requests involving both analysis and a presentation, use the data route for the analysis and the presentation route for the deck. For research that results in a document, combine the research route with the document route only if both evidence handling and document production are material to acceptance. Keep one brief and one set of linked requirements across routes.

Before selecting a route, identify the requested output and the tools actually available. A route describes a method; it does not grant access to a service or guarantee a result. If a route file is unavailable in the installed package, use the core workflow and safety rules, state the limitation, and prepare only what the available environment can support.
